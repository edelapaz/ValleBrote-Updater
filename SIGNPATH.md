# SignPath Foundation application

## Before applying

1. Confirm the copyright notice and rights to publish the updater sources under MIT.
2. Create a new public repository for the updater. Copy the contents of this folder to its root as a new Git history. Include hidden directories `.github/` and `.signpath/`. The public source tree consists of those directories, `src/`, and the root build, version, license and documentation files. The configuration includes the public RSA verification key only.
3. Enable GitHub Actions and run the unsigned build on `main`. Publish a standalone release from that run and link its download page to the README's Code signing policy. Replace the draft roles with links to actual author, reviewer and approver accounts or groups, and verify that those members use MFA. Keep the policy wording conditional until accepted.
4. Submit the public repository URL, standalone release URL, successful Actions run URL and Code signing policy URL at [SignPath Foundation](https://signpath.org/apply). Explain that this is the independently maintained updater only. The published updater from the game's download channel demonstrates previous distribution. SignPath decides if the independent project and its release history qualify.

## After acceptance

1. Link the new repository to a trusted GitHub build system in SignPath. Require origin verification, restrict release signing to `main`, and configure manual approval. Load `.signpath/artifact.xml` as the default artifact configuration. It limits signing to the updater and enforces the PE metadata generated by the build.
2. Set the GitHub Actions secret `SIGNPATH_API_TOKEN` with submit permissions for this project. Set repository variables `SIGNPATH_ORGANIZATION_ID`, `SIGNPATH_PROJECT_SLUG` and `SIGNPATH_SIGNING_POLICY_SLUG` to the values assigned by SignPath.
3. Run **Build Valle Brote Updater** on `main` with **sign** enabled. Approve the request in SignPath. Download the `ValleBroteUpdater-signed` artifact after the workflow verifies Authenticode and the timestamp.
4. Verify with `signtool.exe verify /pa /all /tw /v ValleBroteUpdater.exe`. Require exit code 0 and an explicit timestamp in the output. For a game release, package the signed updater before calculating hashes and signing the game release manifest.
5. Verify the actual upgrade on Windows with Smart App Control active. Start with a clean copy of 0.14.0, select the update from the menu, confirm the restart in 0.14.1 and load a copy of the user's profile. Compare the original profile hash before and after.
